Write, edit, and execute queries in the <ConsoleIcon name="sql editor"/>.

:::note
PG Studio is on by default. If it is off for your organization, you cannot run queries in
the <ConsoleIcon name="sql editor"/>. Instead, the editor shows a message to contact Aiven
support. Aiven manages this control. To change it, contact the Aiven support team. See
[Manage PG Studio and AI features](/docs/products/postgresql/howto/pg-studio/security-connections#manage-pg-studio-and-ai-features).
:::

## Write SQL manually

1. In the <ConsoleIcon name="sql editor"/>, enter your query.

   :::tip[Use `Tab` to autocomplete]
   Press the `Tab` key to autocomplete SQL keywords, table names, column names, and other
   database objects from your schema. When the autocomplete list is open, use the arrow
   keys to move between suggestions and press `Enter` or `Tab` to insert the selected
   suggestion. Press `Esc` to dismiss autocomplete.
   :::

1. Click **Run**, or press `Cmd+Enter` on macOS or `Ctrl+Enter` on Windows and Linux.
1. View the results in the results panel.

The autocomplete feature helps you write queries faster by suggesting:

- SQL keywords and clauses: `SELECT`, `FROM`, `WHERE`, `JOIN`
- Table names from your selected schema
- Column names from tables in your query
- Database functions and operators

## Run a single query

:::note
When the editor contains multiple SQL statements and you don't select any text, **Run**
executes only the statement where your cursor is placed.
:::

1. In the <ConsoleIcon name="sql editor"/>, place your cursor inside the query you want
   to run, without selecting any text.
1. Click **Run**, or press `Cmd+Enter` on macOS or `Ctrl+Enter` on Windows and Linux.
1. View the results in the results panel.

This is useful for:

- Testing individual queries from a larger script
- Iterating on a single query while keeping other statements in context
- Testing each subquery independently before combining a complex query
- Verifying data in a specific table without executing setup or cleanup statements

## Run multiple queries

You can write several SQL statements in the editor and run them all at once. Select the
statements to run. The editor runs them sequentially and displays the results in separate
tabs.

1. In the <ConsoleIcon name="sql editor"/>, write your SQL statements:

   ```sql
   SELECT count(*) FROM orders;
   SELECT * FROM users LIMIT 10;
   ```

1. Select all the statements you want to run.
1. Click **Run selected**, or press `Cmd+Enter` on macOS or `Ctrl+Enter` on Windows and
   Linux.
1. View the results in the results panel. When more than one statement runs, each result
   appears in its own tab labeled **Query 1**, **Query 2**, and so on:
   - A red error indicator on a tab means the statement encountered an error. If a
     statement fails, execution stops and remaining statements are not run. Results from
     statements that completed before the error are preserved.

This is useful for:

- Running a sequence of setup, query, and cleanup statements in one go
- Executing a batch of related queries and comparing their results
- Validating multiple statements before saving or sharing a script

## Execute queries

When you run a query, whether generated by the AI or written manually:

- The editor runs the query against the selected source database and schema.
- The results panel displays your query results. When running multiple statements, each
  result appears in its own tab.

## Export query results

Take your query results out of the <ConsoleIcon name="sql editor"/>, as a CSV file or as
CSV text on your clipboard.

1. In the <ConsoleIcon name="sql editor"/>, run your query.
1. In the results panel, click <ConsoleIcon name="download or copy results"/>, then click
   one of the following:
   - **Download CSV**: Saves the results to a file named `results-TIMESTAMP.csv`, where
     `TIMESTAMP` is the UTC time of the export, for example
     `results-2026-10-12T14-05-09.csv`.
   - **Copy as CSV**: Copies the results to your clipboard.

The export options appear only when a query returns rows. A query that fails or returns
no rows shows no export options.

### What the export contains

- **Column names**: The first row holds the column names, in the order your query returns
  them. The export keeps duplicate column names as they are.
- **Rows**: The export covers all rows fetched for the query, not only the rows on the
  page you are viewing.
- **Truncated results**: When results are truncated because of the result size limit, the
  export holds the truncated set, not the full result of your query. To export more rows,
  refine your query or add a `LIMIT` clause. See
  [Query execution limits](#query-execution-limits).
- **Quoting**: The export quotes and escapes values that contain a comma, a double quote,
  or a line break.
- **Empty values**: The export writes `NULL` as an empty, unquoted field, and an empty
  string as a quoted empty field. This matches the CSV output of the PostgreSQL `COPY`
  command.
- **JSON**: The export writes objects and arrays as JSON text.

:::note
You can export results only from the results panel in the
<ConsoleIcon name="sql editor"/>. When you preview table data in
<ConsoleIcon name="pgtables"/>, no export option is available.
:::

## Query execution limits

The editor applies these limits to query execution:

- Statement timeout: 30 seconds
- Lock timeout: 10 seconds
- Connection timeout: 10 seconds
- Result size: Large results are truncated. To see specific rows, add a `LIMIT` clause or
  refine your query.
- Maximum statements per run: 10
- **Rate limiting:** 15 query executions per 10 seconds per user per service
- **AI rate limiting:** One AI request every two seconds per user per service

## Browse tables while you write queries

While you write queries in the <ConsoleIcon name="sql editor"/>, you can check table names
in the list of schemas and tables for the selected source database. To change the list,
select a different source database.

To preview table data or open the schema map, use <ConsoleIcon name="pgtables"/>. See
[Explore your tables](/docs/products/postgresql/howto/pg-studio/get-started#explore-your-tables).
